## ⚡ 重要提示：推荐使用流式版本

我们提供了两个版本的回填脚本：

### 🌟 **流式版本（强烈推荐）**

```bash
./start_backfill_streaming.sh
```

**核心优势：**
- ✅ **边拉边存**：拉取1页 → 立即保存 → 拉取下一页
- ✅ **中断安全**：按Ctrl+C中断后，已保存的数据不会丢失
- ✅ **智能早停**：根据推文时间自动停止，不会过度拉取
- ✅ **实时进度**：每页都显示拉取和保存进度
- ✅ **成本可控**：实时显示API成本，便于监控

### 📦 批量版本（不推荐）

```bash
./start_backfill.sh
```

**缺点：**
- ❌ 先拉完所有数据再存储
- ❌ 中断后所有API调用浪费
- ❌ 内存占用大
- ❌ 无法及时看到进度

## 💡 核心特性详解

### 1. 智能早停机制

脚本会检查每一页最后一条推文的时间：
- 如果推文时间 **早于** 回填截止时间（例如7天前）
- 立即停止该list的翻页，节省API调用
- **不需要手动设置最大页数**

示例：
```
回填7天，截止时间：2024-12-23 00:00:00
拉取到推文时间：2024-12-22 23:30:00
→ 触发智能早停，停止翻页
```

### 2. 边拉边存模式

**传统批量模式的问题：**
```
拉取所有数据 → 处理 → 存储
     ↓
如果中断，所有API调用浪费！
```

**流式模式的优势：**
```
拉取1页 → 立即处理并存储
  ↓
拉取2页 → 立即处理并存储
  ↓
... (如果中断，已保存的数据不会丢失)
```

### 3. 中断恢复

如果回填过程中按下 `Ctrl+C` 或意外中断：
- ✅ 已拉取并保存的数据**不会丢失**
- ✅ 重新运行脚本会继续回填剩余数据
- ✅ 数据库自动去重，不会有重复数据

## 📞 常见问题

### Q: 中途中断了，需要重新开始吗？
**A:** 不需要！已保存的数据不会丢失，重新运行会继续回填剩余数据。数据库会自动去重。

### Q: 如何知道回填了多少天的数据？
**A:** 脚本会根据推文时间自动停止，日志会显示"智能早停触发"，表示已经拉到指定天数的数据。

### Q: 如果某个list的数据特别多怎么办？
**A:** 不用担心，智能早停会在推文时间超出范围时自动停止，不会无限拉取。

### Q: 回填期间可以同时运行正常爬虫吗？
**A:** 可以，但建议错开时间运行，避免API限流。
